为隐私而生的分层防御

从应用协议到内核网络栈，每一层都假设对手已经拿到数据库。

E2EE

libsignal X3DH + Double Ratchet

不自研密码学。IdentityKey / SignedPreKey / OneTimePreKey 在客户端生成，私钥入 flutter_secure_storage。

Zero-Knowledge

只存账号 ID 与 PHC

account_id = SHA-256(username ‖ pepper)，登录用 HMAC(nonce) 挑战；服务端永不接触明文密码。

Sealed Sender

盲令牌发信

信封投递后清除路由元数据，ack 即删除；离线密文 24h TTL 兜底，服务端不知道谁发给谁。

Runtime Defense

多层限流

WS Origin 精确白名单、每 IP 连接数、预密钥与信封令牌桶、distinct-target 滑动窗口。

Policy Sidecar

Kotlin + Redis Streams

结构化并发消费事件，Redis TIME 时钟，跨维规则（IP→账号比值、重连频率）下发封禁。

Kernel

eBPF/XDP LPM 黑名单

封禁 IP 在内核态直接丢包，SIGTERM 显式 detach，RAII 封装 libbpf，CI 启用 ASan/UBSan。

安全模型一览

客户端永远是可信边界；服务端只做信封转发与准入控制。

单一配置源

所有服务器配置收敛到一个文件，渲染派生出容器、反向代理、策略与内核过滤。

# config/config.yaml（节选）
server:
  host: 127.0.0.1
  port: 8080
  public_url: https://chat.example.com
  ws_allowed_origins: ["https://chat.example.com"]
jwt:
  secret: ${openssl rand -hex 32}
  ttl: 24h
crypto:
  pepper: ${openssl rand -hex 16}
  argon2: { memory_kib: 65536, iterations: 3, parallelism: 1 }
defense:
  rate_limits: { ws_per_ip: 32, prekey_per_min: 120, envelope_per_min: 240 }
  xdp: { enabled: true, iface: eth0 }
  crowdsec: { lapi_port: 8081 }
# make config  →  deploy/.env, caddy.env, acquis.yaml, application.yaml
